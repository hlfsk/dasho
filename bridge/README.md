# OSC Bridge — подключение мобильных приложений напрямую

Мост принимает OSC по UDP (так шлют все iOS/Android-приложения)
и пересылает в браузер по WebSocket. **Без Chataigne, без OBS.**

## Запуск

Двойной клик по **`start-bridge.command`**.
В чёрном окне появится:

```
═════════════════════════════════════════════════════════════════════
  lupsmachine-v2 OSC bridge
═════════════════════════════════════════════════════════════════════

  В мобильных приложениях укажи как target host:
    192.168.1.42 : 9000      ← это IP твоего Mac в WiFi

  В нодах OSC-вход / NDI+OSC введи:
    ws://localhost:8080
═════════════════════════════════════════════════════════════════════
```

⚠ **iPhone/iPad и Mac должны быть в ОДНОЙ Wi-Fi сети.**

## Как настроить твои мобильные приложения

| Приложение | Что шлёт | Как настроить |
|---|---|---|
| **ZIG SIM** | Все сенсоры (accel, gyro, gps, micro pitch) | Settings → IP = IP Mac · Port = **9000** · протокол = OSC |
| **GyrOSC** | Гироскоп / акселерометр / multitouch | Host: IP Mac · Port: **9000** |
| **SeeOSC** | Кастомные слайдеры/кнопки | Settings → OSC IP = IP Mac · OSC port = **9000** |
| **iKeleton OSC** | Скелет тела | Settings → OSC remote = IP Mac · port = **9000** |
| **Mrmr** | Контроллеры на экране | Edit → Connections → Add → Host = IP Mac · port = 9000 |
| **Clean OSC** | Чистый OSC-controller | Settings → IP = IP Mac · port = **9000** |
| **Data OSC** | Данные с сенсоров | как Clean OSC |
| **Monitor OSC** | Мониторинг | как выше |
| **Jockey OSC** | DJ-фейдеры | как выше |
| **TouchOSC** | Кастомные пульты | host = IP Mac · port = **9000** |

## Где смотреть IP Mac

Mac → Системные настройки → Сеть → твой Wi-Fi → справа IP-адрес (обычно `192.168.x.x`).
Или нажми кнопку **🔍 Узнать IP Mac** прямо в нашей OSC-ноде.

## В нашем приложении (lupsmachine-v2)

1. Запусти этот мост (`start-bridge.command`).
2. Открой `http://localhost:8889` (приложение).
3. Добавь ноду **📡 OSC вход** или **📡 NDI + OSC**.
4. WebSocket URL: `ws://localhost:8080` → Подключить.
5. Шли OSC с iPhone → в логе ноды появятся сообщения.

## Что попадает в какие выходы ноды

- Сообщения `/1`, `/2`, ... `/8` → выходы `slot1..slot8` (числа)
- Сообщения `*orientation*`, `*attitude*`, `*rotation*` → `tilt_x`, `tilt_y` (NDI+OSC нода)
- Сообщения `*accel*` с большой амплитудой → `shake!` триггер
- Любое сообщение → `last` (последнее число) + `trigger!` (импульс)

## Отдельно про NDI приложения (iDepth NDI, Camare)

NDI идёт **не через этот мост**. Установи бесплатные NDI Tools на Mac
→ запусти **NDI Webcam Input** → выбери источник iPhone →
наша **iPhone-камера** или **NDI + OSC** нода видит как webcam.

Эти приложения шлют видео по NDI, не OSC. Поэтому им мост не нужен.

## Отдельно про midimittr

`midimittr` — это **MIDI bridge**, не OSC. Он создаёт виртуальный
MIDI-порт на Mac. Наша нода **🎹 MIDI вход** через WebMIDI его увидит
автоматически. Тоже без моста.

## ngrok (если Mac и iPhone в РАЗНЫХ сетях)

Не нужен в локальной сети. Но если хочешь, например, показать шоу
друзьям через интернет:

```
ngrok http 8889                           # туннель для самого приложения
ngrok tcp 8080                            # туннель для WebSocket OSC моста
```

Для UDP-OSC прямой туннель сложнее — `ngrok tcp 9000` работает только
с TCP-OSC (некоторые приложения поддерживают). Проще оставить мобилку
в одной сети с Mac.

## Проблемы?

| Симптом | Причина |
|---|---|
| Окно сразу закрылось | Нет Node.js — поставь с https://nodejs.org (LTS) |
| OSC не приходит | iPhone/Mac в разных сетях, или firewall блокирует UDP 9000 |
| Браузер не подключается | Не запущен мост, или ws://localhost:8080 не верный |
| `Address already in use` | Другой OSC-приёмник занял порт 9000 — закрой его |
